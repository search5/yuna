# Yona → Yuna 마이그레이션 프로젝트 전용 감사 규칙

이 규칙은 yona-convert 프로젝트에서 Antigravity가 항상 준수해야 하는
코드 분석 및 감사 작업의 행동 기준을 정의한다.

---

## 필수 준수 사항

### 파일 읽기

- 레거시 소스 디렉터리: `legacy-yona/app/`
- 신규 소스 디렉터리: `yuna/src/main/kotlin/com/github/search5/yona/`
- 기존 감사 문서: `yuna/docs/PARITY_BACKLOG.md`, `yuna/docs/TEMPLATE_BACKLOG.md`
- **어떤 파일에 대해서도 "읽었다"고 주장하려면 반드시 `view_file` 도구를 실제
  호출해야 한다. 대화 맥락의 요약으로 대체하는 것은 허용되지 않는다.**

### 결과물 저장

- 신규 감사 문서는 반드시 `yuna/doc2/` 디렉터리 아래의 `.md` 파일로 저장한다.
- 대화창 응답만으로 분석 결과를 전달하고 "완료"를 선언하는 것은 허용되지 않는다.

### 기존 문서 선행 확인

- 새로운 감사 작업을 시작하기 전에 반드시 `yuna/docs/PARITY_BACKLOG.md`의
  해당 섹션을 먼저 읽어, 클로드가 이미 발견하고 기록한 항목과 중복되지 않도록
  확인한다.
- 클로드가 이미 `[x]`(완료) 처리한 항목을 재발견한 것처럼 서술하지 않는다.

### 코드 인용 의무

- "이식되었습니다", "동일합니다", "누락되었습니다" 같은 결론은 반드시
  해당 파일의 클래스명·메서드 시그니처·라인 번호를 인용해야 한다.
- 인용 없는 결론 서술은 사실 확인이 불가능한 추정이므로 작성하지 않는다.

---

## 이 프로젝트의 아키텍처 배경 (항상 염두에 둘 것)

- **레거시**: Play Framework 2.3 (Java), Twirl 템플릿 242개, Ebean ORM
- **신규**: Spring Boot 3.x (Kotlin), Thymeleaf, JPA/Hibernate, MariaDB/PostgreSQL
- **주요 결함 추적 문서**:
  - `yuna/docs/PARITY_BACKLOG.md` — 백엔드 동치성 결함 관리 대장 (1,565라인)
  - `yuna/docs/TEMPLATE_BACKLOG.md` — 템플릿 이식 상태 관리 대장 (881라인)
- **기존 감사 결과물**: `yuna/doc2/` 디렉터리

---

## 절대 하지 말 것

- 클로드가 이미 수천 줄로 기록한 내용을 5~10줄 요약으로 대체하는 행위
- `view_file` 없이 코드 내용을 서술하는 행위
- 분석 결과를 대화창에만 쓰고 파일로 저장하지 않는 행위
- "전수 분석을 완료했습니다"를 실제 파일 탐색 없이 선언하는 행위
